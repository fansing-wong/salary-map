# 薪酬地图：后续功能设计

**状态：** 持续实现中 · **目标：** 让跨国跨城市工作机会和迁移路径能按可解释、可追溯的口径比较

## 产品原则

1. 先呈现可核验的事实，再呈现估算和建议；三者使用不同标签。
2. 任何跨币种排名都要写明换算口径、参考期和数据来源。
3. 个人输入默认只保存在浏览器，不上传、不用于公共统计。
4. 用户可以看到推荐分如何形成，并能调整偏好；应用不替用户做最终决定。
5. 招聘广告、官方薪资统计、社区投稿是不同类型的数据，分开汇总。

## 优先级

| 阶段 | 功能 | 用户价值 | 发布门槛 |
|---|---|---|---|
| P0 | 统一数据口径与来源追踪 | 不再把模拟数据误读为市场事实 | 每条公开记录可查看来源、统计期、币种、税前/后、均值/中位数和工时口径 |
| P1 | 跨币种购买力比较 | 回答“搬去另一个城市后，收入实际能买到什么” | 外汇换算与物价平价分开显示；每个结果带基准币种和数据年份 |
| P2 | 税后收入与储蓄空间 | 把税前工资转成更接近个人预算的比较 | 必须有地区税务来源/规则版本；显示估算区间和免责声明 |
| P3 | 个性化推荐 | 让建议匹配用户真正重视的因素 | 用户可调整权重、查看分项得分、保存多个方案、查看内置方案排名稳定性（核心已实现） |
| P4 | 数据刷新和监控 | 维护者知道数据何时失效或采集失败 | 来源许可和刷新频率明确；失败时保留最后成功数据并显示过期状态 |
| P5 | 国家/地区层级对照与出海路线 | 比较留在本国、跨城市或迁往海外的工作与长期居留方案 | 地理层级与签证状态分开；路线引用政府来源并随政策复核 |
| P6 | 职业转型、优势衰减与备份路线 | 评估转相邻职业、跨行或保留现有优势的收入与执行风险 | 目标岗位证据、训练成本、个人情景区间和可逆性清楚；不伪造成功概率 |


### P3 本轮实现

- 默认提供均衡、购买力优先、时薪优先、低强度优先四种权重方案。
- 用户可调整权重并保存/删除多个命名方案；方案和权重仅保存在当前浏览器。
- 推荐分仍按缺失项规则处理，不将缺失数据解释为零分。现已增加四种内置方案下的前3排名一致性提示；它不代表成功概率或统计置信度。后续通过用户反馈校准预设，而不是宣称预设适合所有人。
## P5：地域择业与迁移路线

- 对照维度：同职业比地域、同地域比职业；国家 → 省/州/大区 → 城市/都会区。按来源本身的数据粒度展示。
- 本国/海外：用户主动指定本国，再分别查看本国机会、海外机会；不从浏览器位置自动推断国籍或居住地。
- 迁移阶段：短期探路、可合法工作、长期工作/居留、永居、入籍。访客/旅游身份不作为工作路线。
- 路径类型：雇主担保、积分/技能、地区提名、留学后工作、公司内调派、工作假期、人才/杰出能力、创业/投资、家庭团聚、指定行业项目。
- 适配信息：国籍、年龄、职业、学历、资历、语言、预算、家庭、愿意投入的时间和是否接受偏远地区。条件不足时列为待核实，不标为“可行”。
- 薪酬排序与移民资格独立呈现。路线卡可关联同职业 PPP 余额、实际时薪、工作强度、税务与搬迁成本情景。
- 当前首批国家和官方路线入口见 [国家数据覆盖计划](COUNTRY_COVERAGE.md) 与 [出海工作/居留路径](MOBILITY_PATHWAYS.md)。政策变化快，需在每次数据发布中记录核对日期。

## P6：职业转型与韧性

- 并列比较强化当前优势、相邻转型、跨领域转型、防守备份四条路线。
- 用户指定“优势衰减”信号和触发阈值；工具只显示证据，不自动宣判职业消失或个人不适配。
- 用目标岗位任务和技能对照当前经验，标出可迁移技能、证据强弱、资格/语言差距和训练成本。
- 连接目标国家/城市工资、购买力、工时、工作强度与签证限制，形成收入下限和迁移约束。
- 用低/中/高情景展示收入回撤、训练时间、储蓄跑道和职业回转成本。数据缺失时让用户输入范围，不制造个人成功概率。
- 以作品、从业者反馈、面试、执照认可和目标 offer 作为继续投入的阶段门槛。
- 详细规格及官方职业资料来源见 [职业转型与优势衰减情景](CAREER_SCENARIOS.md)。

## P0：数据可信度层

### 每条记录的数据合同

建议将目前 CSV 行模型扩展为以下逻辑字段（字段名可在实现时定稿）：

```json
{
  "location": {"country": "SG", "admin1": "Central Region", "city": "Singapore"},
  "occupation": {"name": "Software Engineer", "code": "", "taxonomy": ""},
  "compensation": {"amount": 7200, "period": "month", "currency": "SGD", "gross_net": "gross", "statistic": "median"},
  "hours": {"contract_weekly": 40, "overtime_weekly": null, "commute_weekly": null},
  "cost_budget": {"amount": null, "currency": "SGD", "household": "single", "housing": "rent"},
  "labor_intensity": {"score": null, "method": "user_estimate"},
  "provenance": {"publisher": "", "url": "", "reference_period": "", "retrieved_at": "", "license": "", "data_type": "official_statistic"}
}
```

关键规则：缺失值保持 `null`，不能用 0 代替；城市薪资未发布时，不要把国家均值伪装成城市均值；统计值和用户自填 offer 不混合平均。

### 页面变化

- 在数据表加入“数据类型 / 参考期 / 来源”入口。
- 顶部显示最近成功更新时间、记录数量、来源数量和采集状态。
- 数据超过来源自身更新周期时标记“可能过期”，不静默删除旧记录。
- 演示数据固定加“模拟数据”标识。

## P1：购买力与汇率

### 三种金额并列展示

1. **当地税前月薪**：保留本地名义金额。
2. **换算金额**：按某一参考日的外汇汇率换算到用户选定的展示币种，用于现金流/跨境汇款视角。
3. **当地购买力**：以官方 PPP / 价格水平指标换算，作为跨地区商品与服务购买力的粗略比较。

PPP 和汇率不是同一指标，不能混为一个“统一货币薪资”。默认推荐依据优先使用购买力调整后的可支配余额，旁边同时提供名义金额。

### 个人预算计算

- 月可支配收入 = 月税后收入 − 住房 − 其他基本生活预算。
- 购买力余额展示本地币数值；跨区比较使用同一基准币种的 PPP 调整金额。
- 可选情景：合租 / 独居、通勤方式、储蓄目标、家庭人数。
- 生活成本不再采用项目内固定猜测值；用户输入优先，其次为注明年份的城市价格数据。

### 重要边界

PPP 适合比较总体价格水平，不代表用户个人消费篮子。住房、医疗、教育、汇款与个人税务差异可能很大。默认结论应为“预算情景比较”，而不是生活质量或移民结论。

## P2：税后估算

第一版仅支持配置明确的国家/地区，按官方公开税表和规则版本计算。每个地区适配器需记录：适用年份、居民身份假设、税前工资构成、社保/养老金规则、抵扣项和官方来源链接。无法判断的身份/抵扣信息由用户输入或显示区间，不做隐式推断。

## P3：透明的岗位建议

推荐分拆为可调分项，而不是黑盒总分：

- 购买力结余 40%
- 计入通勤与加班的有效时薪比较 35%
- 劳动强度 15%
- 资料口径完整度 10%

上述为默认值；仪表盘已提供滑杆调整、四种内置方案切换、自定义方案本机保存，以及方案间前3排名稳定性提示。只有至少4个候选可评分、且至少两种内置方案可比较时才给出稳定性比例；按前3名分数线计入并列，较稳定阈值为进入前3的方案比例不低于 75%，不高于 25%标为偏好敏感。它是权重情景比较，不是概率或置信度。资料口径完整度表示字段是否齐全，不等同于统计质量或数据新鲜度。每行显示分项和样本数；预算、强度等个人输入仅存于本机。默认权重仍需通过用户反馈校准。

“劳动强度”现阶段是个人主观评分，不应由职位名称自动赋值。未来可用可解释维度收集：体力负荷、工作节奏、情绪压力、排班可控性、加班可预期性，并分别显示。

## P4：自动更新架构

### 已实现的刷新状态底座

- 刷新器将 BLS、已配置 CSV 和宏观指标拆成独立步骤；一个来源失败不会跳过其他来源。
- 每个步骤记录最近尝试、最近成功或失败；数据文件通过临时文件校验后原子替换，失败时保留最近成功快照。
- GitHub Actions 提交 `data/status.json` 后仍以失败状态结束，避免把部分刷新错误伪装成成功；仪表盘读取运行状态。
- robots.txt 明确拒绝的来源标为受限，保留旧快照并在 Actions 与页面发出警告；不尝试绕过抓取限制。其他网络或解析错误仍使工作流失败。
- 页面暂定工资参考期 2 年、汇率 7 天、PPP 参考年 3 年的复核提醒阈值。后续应按各来源更新节奏细化，并增加数据覆盖、样本量和连续失败告警。

### 数据源分层

1. **官方薪资统计**：适合做地区/职业基线，按原统计口径保留平均数或中位数。
2. **官方生活价格 / PPP / 汇率**：展示参考期，不假设都实时更新。
3. **公开招聘广告**：表示近期市场报价样本，保存去重后的薪资区间和发布时间，不等同于已成交工资。
4. **社交平台内容**：只接获准官方 API、授权导出或官方公开数据接口；标为帖子样本并保留许可与采集时间，不用于直接估算平均薪资。不可绕过登录、验证码、访问限制或速率限制。

### 更新行为

- 来源清单显式配置访问方式、许可、刷新周期、字段映射、统计口径和归属地区。
- 每个来源独立失败和重试；失败时继续发布最近成功版本，并标明时间。
- 汇总文件通过临时文件生成并校验后原子替换，避免半份数据覆盖。
- 工作流只在内容变化时提交，记录每次采集状态；不要把令牌放进仓库。
- 首期优先加官方开放 CSV / JSON，暂停没有稳定公开接口的爬取目标。

## 下一版本的范围建议

优先交付 **P0 + P1 的最小闭环**：补齐样例字段与来源标记；增加展示币种、汇率基准日、PPP 年份和个人城市预算；演示记录仍明确标为模拟数据。税务计算和社交平台 API 暂不进入第一版，避免在数据许可、身份假设或统计口径未确认前产生误导性排名。

## 验收清单

- 每条记录能回答：谁发布、何时统计、何时抓取、用什么币种和薪资口径。
- 用户能区分名义金额、汇率金额和 PPP 购买力金额。
- 跨币种推荐不再直接比较不同货币的数字。
- 缺失数据以“未知”显示，而不是 0；数据过期有提示。
- 推荐分可展开、可调权重、可查看原始输入；不把主观强度评分伪装成客观测量。
- 任何官方源或平台接口无法访问时，界面明确标识回退到上次数据或模拟记录。
