# Data pipeline

The project accepts openly published CSV datasets only. Each source entry must identify its publisher, URL, update cadence and license. The collector checks `robots.txt`, uses a descriptive User-Agent, applies a per-host delay, sends conditional HTTP requests, validates a fixed schema, and records retrieval time and source metadata. It does not bypass authentication, CAPTCHAs, rate limits, or access controls.

For social networks, use only a documented API with the required app approval and data scope. LinkedIn's Posts API, for example, restricts read permissions for member content to approved users; this project does not scrape logged-in feeds. Social posts can be treated as dated job-posting observations only, never as representative salary averages. Aggregate and label them separately.

`python scripts/refresh_data.py` runs the BLS, Statistics Canada monthly NOC wage importer, configured CSV collector, snapshot merge, and macro refresh independently. It atomically writes `data/status.json` with each component's most recent attempt and last successful run; failed components keep their prior output and cause the GitHub Actions job to fail after the status report is committed. A robots.txt disallow is recorded as `blocked`, keeps the prior snapshot, and emits a workflow warning without treating the restriction as a transient network error. The dashboard reads that report and shows data reference periods, retrieval times, and stale-data warnings.

The Statistics Canada adapter uses the official WDS metadata and coordinate endpoints for table 14-10-0426-01. It requests only the latest average weekly wage for available terminal NOC occupation groups and Canada/province geographies, then records a clearly labeled 52/12 monthly equivalent. Because this Labour Force Survey table aggregates occupations, it does not claim detailed job titles such as software developer. Unknown work hours, costs, and intensity remain null; the first successful workflow run must confirm metadata labels and publish the snapshot.

`python scripts/update_data.py` can still be run by itself to refresh configured CSV sources and `data/latest.json`. The current source registry is intentionally empty until maintainers add a source whose access and redistribution terms they have checked. Refresh outputs are written to a temporary file and atomically replaced only after validation succeeds.
