# Data pipeline

The project accepts openly published CSV datasets only. Each source entry must identify its publisher, URL, update cadence and license. The collector checks `robots.txt`, uses a descriptive User-Agent, applies a per-host delay, sends conditional HTTP requests, validates a fixed schema, and records retrieval time and source metadata. It does not bypass authentication, CAPTCHAs, rate limits, or access controls.

For social-network work-experience observations, use the authorized-export pipeline in [SOCIAL_OBSERVATIONS.md](../docs/SOCIAL_OBSERVATIONS.md). `aggregate_social_observations.py` accepts locally held, authorized JSON/JSONL exports, applies the documented keyword themes, suppresses groups below 30 records, and writes de-identified aggregate counts/rates to `data/social_observations.json`. It makes no network requests and does not scrape pages or logged-in feeds. Keep raw exports, post text, account identifiers, per-post URLs, and tokens out of the repository. Social mention rates are self-selected and context-blind; they are not official salary statistics, representative workplace prevalence, sentiment scores, or recommendation inputs.

`python scripts/refresh_data.py` runs the BLS, Statistics Canada monthly NOC wage importer, configured CSV collector, snapshot merge, and macro refresh independently. It atomically writes `data/status.json` with each component's most recent attempt and last successful run; failed components keep their prior output and cause the GitHub Actions job to fail after the status report is committed. A robots.txt disallow is recorded as `blocked`, keeps the prior snapshot, and emits a workflow warning without treating the restriction as a transient network error. The dashboard reads that report and shows data reference periods, retrieval times, and stale-data warnings.

China data stays in separate versioned snapshots: `data/china_nbs_2025.json` holds national statistical bureau records; `data/china_local_wages_2025.json` holds selected local statistical releases; `data/shenzhen_market_wages_2024.json` holds selected Shenzhen HR salary-survey percentiles for the 2024 survey period, published in 2026; `data/china_wage_surveys.json` stores selected official enterprise salary-survey percentiles for national, Jiangsu, Wuhu and Suzhou sources, preserving each source's reference period and sample counts where released; `data/china_wage_structure_2025.json` holds national and prior interactive comparison tables; and `data/china_east_regions_2025.json` adds wage, industry, Anhui city, Jiangsu focus-city, Guangdong subregion, and resident-income/consumption snapshots for Jiangsu, Zhejiang, Shanghai, Anhui, Fujian and Guangdong. `data/china_employer_types.json` is a source-linked, manually maintained view of available employer-type statistics; it keeps national 2025 data and detailed Nanjing 2024 records separate by reference year. `scripts/update_data.py` normalizes the East China wage snapshots into `data/latest.json`; the scheduled workflow stages the snapshots it refreshes. The employer-type snapshot is manually maintained and should be checked against its cited tables before changes. The enterprise survey snapshot is manually transcribed from official tables, not scraped; verify the source row, unit conversion, reference year, occupation definition and survey scope before changing values. No social-platform pages are scraped; missing hours, tax, commute, individual costs and intensity are not imputed.

The Australia snapshot uses ABS EEH May 2025 all-employee weekly cash earnings by broad occupation group, converted to a monthly equivalent; work hours, tax, commute, costs and intensity are not imputed. It is kept as a versioned source snapshot and is not scraped weekly.

The Statistics Canada adapter uses the official WDS metadata and coordinate endpoints for table 14-10-0426-01. It requests only the latest average weekly wage for available terminal NOC occupation groups and Canada/province geographies, then records a clearly labeled 52/12 monthly equivalent. Because this Labour Force Survey table aggregates occupations, it does not claim detailed job titles such as software developer. Unknown work hours, costs, and intensity remain null; the first successful workflow run must confirm metadata labels and publish the snapshot.

`python scripts/update_data.py` can still be run by itself to refresh configured CSV sources and `data/latest.json`. The current source registry is intentionally empty until maintainers add a source whose access and redistribution terms they have checked. Refresh outputs are written to a temporary file and atomically replaced only after validation succeeds.
